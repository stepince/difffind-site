Suas URLs só são enviadas ao aplicativo {{brand}} quando você clica em Carregar e comparar. O aplicativo busca os dois endereços e compara as respostas. Nada é armazenado nesta página. O aplicativo está disponível, por enquanto, apenas em inglês.

O que você pode comparar com duas URLs

O DiffFind carrega o conteúdo de texto que cada URL retorna, para que você possa comparar:

  • Endpoints de API, como a resposta JSON de um serviço de homologação e de um de produção.
  • Páginas web, comparando o conteúdo que o endereço retorna.
  • Conteúdo hospedado baseado em texto, como feeds XML, arquivos de configuração e documentos de texto simples.

O endereço precisa ser um que o aplicativo DiffFind consiga carregar. Se uma requisição exigir credenciais ou um método específico, coloque-a em um comando cURL e use a comparação de cURL.

Exemplo: homologação versus produção

Este exemplo ilustrativo compara o endpoint de status de um serviço em dois ambientes. As URLs usam o domínio reservado example.com, e as respostas são simplificadas.

Antes (homologação)

https://staging.example.com/api/status

{
  "version": "2.4.1",
  "status": "ok",
  "featureFlags": {
    "newCheckout": true
  }
}

Depois (produção)

https://www.example.com/api/status

{
  "version": "2.4.0",
  "status": "ok",
  "featureFlags": {
    "newCheckout": false
  }
}

O que a comparação informa

  • version mudou de "2.4.1" para "2.4.0".
  • featureFlags.newCheckout mudou de true para false.
  • status não mudou.

A análise semântica opcional pode então descrever o impacto, por exemplo, que um recurso habilitado em homologação ainda não está habilitado em produção. Use Carregar exemplo no formulário acima para experimentar a comparação com uma API de testes pública.

Comparação de URLs e comparação de cURL

A comparação de URLs usa dois endereços. É a forma mais rápida de comparar o que cada endereço retorna.

A comparação de cURL aceita definições completas de requisições HTTP: um método como POST ou PUT, cabeçalhos e um corpo de requisição. Use-a quando as duas requisições diferirem em mais do que o endereço. Veja como comparar respostas do cURL.

Primeiro as diferenças exatas, depois o significado

A comparação léxica identifica adições, remoções e valores alterados exatos e é determinística. A análise semântica opcional a complementa explicando o que as alterações significam. A IA nunca é necessária para comparar duas URLs.

Casos de uso comuns

  • Comparar endpoints de homologação e de produção.
  • Verificar um endereço antes e depois de uma versão.
  • Comparar a resposta de uma API entre duas versões de um serviço.
  • Revisar alterações em uma configuração ou um feed hospedados.
  • Comparar respostas estruturadas com Comparar JSON ou Comparar XML quando você já tem os dados.

Perguntas frequentes

Como comparo duas URLs?

Informe ou cole a primeira URL no lado Antes e a segunda no lado Depois e, em seguida, carregue e compare. O DiffFind carrega o conteúdo de cada endereço e mostra todas as diferenças entre os dois.

O DiffFind consegue comparar o conteúdo retornado por duas URLs?

Sim. O DiffFind carrega o conteúdo de texto que cada URL retorna, como uma resposta de API em JSON, XML ou texto simples, e compara os dois resultados.

Qual é a diferença entre a comparação de URLs e a de cURL?

A comparação de URLs recebe dois endereços. A comparação de cURL recebe dois comandos cURL completos, de modo que cada requisição pode ter o próprio método, cabeçalhos e corpo. Use a comparação de cURL quando uma requisição precisar de mais do que um endereço.

A IA pode explicar as alterações relevantes entre URLs?

Opcionalmente. A comparação léxica exata sempre vem primeiro e funciona sem IA. Depois, você pode adicionar a análise semântica com IA para explicar o que as alterações significam.

Posso comparar endpoints de homologação e de produção?

Sim. Informe a URL de homologação em um lado e a de produção no outro e compare as respostas.
